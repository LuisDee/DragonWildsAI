# Plan after TASK-0 (2026-10-31) — live-first

Sources: `docs/research/2026-10-31-death-loop-forensics.md`, `docs/research/2026-10-31-competent-game-bots.md`, `docs/research/2026-10-31-dogfood-live.md` (live session), `docs/audit-2026-10-31/code_audit.md`.

## Why we were stuck (one paragraph)
The body stopped walking: code guards refused or crawled at 1.1 m/s. It reported the stop in untrue jargon ("movement owner token required" was really our own eat/drink reflex). Haiku then invented a cause, and the Director replanned with Sonnet. No replan can change what the body can do, so the cycle repeated until a turn, budget or time limit ended it. go_to fell from 57% to 17%, and a Sonnet step cost about 5× more. Every reliable bot we surveyed does the opposite. The model makes one goal-level call per journey; code handles re-pathing and unsticking on timers; the model only hears the final, honest outcome; and retry caps sit above the model.

## The new operating goal: a ladder of short live rungs
Rungs are measured live on the dev world, from game state, in minutes. When a rung passes 3/3, move to the next. M1–M6 in GOAL.md stay as the long-term horizon, not the operating gate.

1. **Travel.** A fixed set of about 10 dev-world journeys (near, far, uphill, the temple ramp, a lodestone hop).
   - Body-only via the bridge: ≥ 80% reach the goal.
   - Then from chat, through the brain: ≥ 80%, with ≤ 2 model calls per leg and every failure reason true.
2. **Co-play (30 min).** Follow, fight and gather on request.
   - Count the chat requests completed.
   - Every failure is told truthfully.
   - Never silently stuck, never a death loop.
3. **Fresh-character progression, unaided.** Axe → table/base → cooked food → the next gear tier. Record time and model calls per milestone.

## The fixes, in order (each one: change → live check → keep or bin)
1. **go_to finishes the job itself** (move.lua, after the clean-up restore):
   - if the route ends short (`route_ended_before_goal`, `no_path`, `invalid_route`), walk on: bounded straight/trail steering, keeping only the KillZ check, and fail only on measured non-progress;
   - sprint on remembered routes;
   - deadline `max(120, 3·d/4.5)` s;
   - movement-free reflex owners (eating, drinking) never block, and any remaining busy message names the owner.
2. **An honest trip record** for every move: start/end, metres moved, closest approach, "moving away", "walkable map ends N m short, H m above", "fell H m". The model gets one sentence; the log gets the full row. Add `fell`/`killed_by` to recent_life.
3. **Prompt diet:**
   - strip terrain, barrier and ray dumps from what the model sees;
   - give `state:*` notes a TTL, and delete the stale body_link note;
   - add a "Where:" line (region, height relative to the target);
   - target ≤ 15k tokens.
4. **No-progress breaker:** the same tool, rounded arguments and reason twice with < 2 m net moved → tell the player the specific reason once and park the step. No Director replan on busy/timeout. A per-sub-goal call budget. It informs and caps; it never vetoes.
5. **Director output:** a forced tool call (structured output); drop the advisory second pass.
6. **A route graph from walks that worked** (navmem already records them): typed edges (walk, jump, double jump, Windstep, lodestone), success counts, and native path to the nearest few graph nodes. One real walk up the temple ramp becomes permanent.
7. **Observability:**
   - a per-episode "Haiku saw vs reality" table in `tools/obs.py`;
   - movement-mode / position-correction hooks via hookhub (offline-tested first);
   - vitals.jsonl rotated per day, not truncated.

8. **Live-test findings** (dogfood §3–6):
   - **Where am I:** add position, region and nearest named places to the situation, and let `go_to` take the 514 place names in `data/places_26161880.json`. "Head over to Zanik" failed for lack of this.
   - **Oracle health is a visible fact:** when the nav oracle is down, the result says so. It is never mis-labelled `nothing_in_range` or `path_blocked`. A stopped oracle reproduced the death loop live (14 Haiku calls, 0 m moved, HP 100 → 24).
   - **Code never talks over the model:** no canned or untrue chat lines, and failure details are not read aloud when Haiku chose silence.
   - **The fed reflex** doesn't consume what the model just made for a task. Its events reach the model promptly, not only after a chain ends.
   - **Survival alarms** are dropped only when the stat actually recovered.

Not now: vision or perception models, and new guard layers. A semantic layer is needed only for places and floor/connectivity (items 6 and 8), not a perception model.

## Fast iteration
- Keep the client up; the Lua hot-reloads.
- One command runs the rung-1 journeys body-only (no model calls) and prints a success rate. Run it after every movement change.
- Brain checks: 2–3 chat requests, ≤ 30 calls, spend read from `tools/spend.py`.
- Commit what works; revert what doesn't. No design notes, no review chains.
