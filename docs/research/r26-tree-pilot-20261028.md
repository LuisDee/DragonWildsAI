## Root cause supported by route evidence

Client logs show local route segments followed by raw-goal straight steering.
At04:31:44 local waypoints were exhausted; straight steering continued up to
6.8m/s. Four structured server responses to this exact destination were no_path
with zero points (04:31:28/37/41/46); the ordered plain log's next response was
start_off_navmesh, an association rather than a matching structured response.
No successful oracle path or partial path for this destination is evidenced.

`move.lua` clears a failed/timed-out oracle path but keeps steering while the
request is pending; default aim remains the raw goal. Local segment exhaustion
returns to that default. This is a concrete unverified-travel fallback, not
proof of a cliff or a specific projection failure. The separate possibility
of exhausted partial paths falling through is a source-code risk, not an
observed partial route in this run. nav_id is preserved across ordinary move
resets; earlier private speculation that it reset each move was corrected.

The focused design holds oracle-required long-trip input pending evidence,
retains actual single-flight work through local timeout, handles no_path and
partial endpoints truthfully with bounded ownership-aware retry, and preserves
explicit direct/nearby/traversal behavior. It propagates existing projection and
partial metadata without converting unknown into false. The design is approved
for bounded implementation/tests, not implemented or live-proven. The broader
continuous-support guard remains open.
