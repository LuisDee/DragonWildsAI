Game build referenced by third-party notes: 25632050 (UE 5.6.1, `++dominion+hotfix-CL-247068`), UE4SS v3.0.1 beta, git `0196ef29` ("UE4SS for RSDragonwilds", Nexus mod #4). Our own build ID must be re-checked.

## 0. Summary

1. **Spawning from Lua works in Dragonwilds.** `World:SpawnActor(BPClass, {X=,Y=,Z=}, {Pitch=,Yaw=,Roll=})` spawned a replicated, mineable `BP_DivineRock_*_C`. Source: Starfall `DISCOVERY.md` (High). It was tested on a solo/host session, not yet on a dedicated server with a remote client. Starfall says so itself.
2. **Native `/Script/Dominion.InteractableNPC` returns nothing from `SpawnActor`. Its Blueprint subclass `/Game/Gameplay/NPCs/BP_BaseInteractableNPC.BP_BaseInteractableNPC_C` spawns fine.** Spawn Blueprint classes, not native or abstract ones (High, same source).
3. **The player character depends on its PlayerController.** Inventory, progress, ping and map components hang off the controller, not the pawn. A player-class pawn with only an AIController will lack all of them (High for where the components live; Med for the consequences). So **approach (b), an existing NPC/creature class, is much more likely to pass the Phase 4 gate.** Try (a) only afterwards, as a stretch.
4. **Replication defaults for the NPC class are a trap.** Starfall probed `BP_BaseInteractableNPC_C`: `bReplicates=true`, `bReplicateMovement=false`, `NetCullDistanceSquared=225,000,000` (150 m), `NetDormancy=4` (DORM_Initial). A walking companion needs `SetReplicateMovement(true)` and `SetNetDormancy(DORM_Awake)`. Use the setter UFunctions, not raw property writes, because of the push model (section 4).
5. **No spawn cheat is available.** `UDominionCheatManager` has `domSetTime`, `domAddItem` and others, but they are empty in the shipped game. The game has no built-in console (section 5).
6. **No public example of a Dragonwilds mod that spawns an AI-driven creature or makes one follow a player.** I found none in Palworld, Hogwarts Legacy or other games either. The closest are Starfall (spawns rocks/NPC shell) and a Nexus "Pet Rock" follower, which I could not read (403). We are doing new work here.
7. **Biggest unknown: whether the navmesh exists on the server around the companion.** Dragonwilds uses World Partition (`WorldPartitionSubsystem` appears in Starfall's notes). Navmesh may be invoker-driven or streamed. Test this before anything else AI-related (plan step 5).

## 1. Spawning an actor from UE4SS Lua on a server

### 1.1 What the UE4SS API gives you

- `UWorld:SpawnActor(UClass ActorClass, FVector Location, FRotator Rotation)` returns an `AActor`, or an invalid object on failure. The docs say it uses `UGameplayStatics:BeginDeferredActorSpawnFromClass` then `UGameplayStatics:FinishSpawningActor`. Source: https://docs.ue4ss.com/dev/lua-api/classes/uworld.html (High).
- The Lua binding reads Location and Rotation **as tables only** (a userdata argument throws "No overload found"). Location keys `X`, `Y`, `Z`; rotation keys `Pitch`, `Yaw`, `Roll`. Missing keys default to 0. Source: `UE4SS/src/LuaType/LuaUWorld.cpp` on `main`, https://github.com/UE4SS-RE/RE-UE4SS/blob/main/UE4SS/src/LuaType/LuaUWorld.cpp (High for `main`; the Dragonwilds UE4SS 3.0.1 build may differ slightly, but Starfall's calls use exactly these tables).
- The wrapper always spawns at scale 1 with the default transform. Setting scale after spawn works for rocks (`SetActorScale3D`, Starfall) but PR #864 says it "may not work for some actors, such as animated characters". PR #864 (still open) proposed `SpawnActor(Class, Loc, Rot, Scale)`; maintainers prefer exposing an `FTransform` overload. Source: https://github.com/UE4SS-RE/RE-UE4SS/pull/864 (High that it is open and unmerged).
- **Because the wrapper finishes spawning immediately, you cannot set `AIControllerClass` or `AutoPossessAI` between begin and finish.** Either (i) spawn, then set properties and call `pawn:SpawnDefaultController()` yourself, or (ii) call the two `UGameplayStatics` functions directly. See 1.3.
- Known crash: `UWorld::SpawnActor()` crashed after about 3 to 10 spawns in a Half Sword (UE 5.1, UE4SS 3.0.1) report. The stack went through `FinishSpawningActor` and `execLocalVariable`. Still open, no maintainer fix. The game's own `CheatManager::summon` did not crash. Source: https://github.com/UE4SS-RE/RE-UE4SS/issues/527 (High that it exists; Low that it affects Dragonwilds, since Starfall spawned many rocks without noting a crash). Mitigations: spawn on the game thread only, rate-limit, keep a handle to every spawned actor, and spawn one companion rather than many.

### 1.2 Finding the world and the class

**World.** On a dedicated server there is usually no local `PlayerController`.
- `UEHelpers.GetWorld()` tries the player controller first, then falls back to `GameInstance:GetWorld()`, else returns an invalid object. Source: https://raw.githubusercontent.com/UE4SS-RE/RE-UE4SS/main/assets/Mods/shared/UEHelpers/UEHelpers.lua (High).
- `UEHelpers.GetGameplayStatics()` caches `StaticFindObject("/Script/Engine.Default__GameplayStatics")` (same source, High).
- Release notes: `AActor:GetWorld()` and `AActor:GetLevel()` now return an *invalid object*, not nil. So always test `:IsValid()`. Source: https://github.com/UE4SS-RE/RE-UE4SS/releases/tag/experimental-latest (Med; search snippet only).
- Starfall's own host code used the local controller and says "Dedicated servers stay out. Nothing has been tried on one, and the host code assumes a local player" (`COOP.md` line 40). So nobody has published a verified dedicated-server `GetWorld` path for this game. Candidates, all UNTESTED: `FindFirstOf("GameInstance"):GetWorld()`, `FindFirstOf("GameModeBase"):GetWorld()`, or `FindAllOf("PlayerController")[1]:GetWorld()` once a player has joined. RSE-Fixes does run on a dedicated server and uses `FindAllOf('PlayerController')` filtered by `IsLocalController` to find remote players (https://github.com/kevinw9092/RSE-Fixes, `Scripts/buildings.lua`, `B.remotePlayers`) (Med).

**Class.** Blueprint classes must be loaded in memory before `StaticFindObject` finds them.
- `StaticFindObject(path)` takes the full name without the type prefix, e.g. `/Script/Engine.Character`. It finds only objects already in memory. Source: https://docs.ue4ss.com/lua-api/global-functions/staticfindobject.html (High).
- `LoadAsset(path)` loads game assets not yet loaded, including game-feature plugin paths like `/UmbralSands/...`. A bad path fails cleanly. Source: Starfall `DISCOVERY.md` line 54 (High).
- Blueprint class path form: `/Game/Gameplay/UtilityMagic/PerkSpells/DivineRock/Types/BP_DivineRock_Iron.BP_DivineRock_Iron_C` (High, works). Other verified paths: `/Game/Gameplay/NPCs/BP_BaseInteractableNPC.BP_BaseInteractableNPC_C`, `/Game/Gameplay/NPCs/Fellhollow_NPCs/BP_NPC_Death.BP_NPC_Death_C`, `/Game/Gameplay/Character/Player/BP_PlayerController.BP_PlayerController_C` (High; Starfall and RSE-Toolbag).

### 1.3 Working snippets

**A. Verified in Dragonwilds (rock), adapted.** Source: https://github.com/brucestarlove/Dragonwilds-UE4SS-AI-devkit, `probes/starfall/spawn_rock.lua`, and Starfall `Scripts/game/world.lua` `World.spawn`. (High)

```lua
local path = "/Game/Gameplay/UtilityMagic/PerkSpells/DivineRock/Types/BP_DivineRock_Iron.BP_DivineRock_Iron_C"
local cls = StaticFindObject(path)
if not (cls and cls:IsValid()) then pcall(LoadAsset, path); cls = StaticFindObject(path) end
local actor = world:SpawnActor(cls, { X = x, Y = y, Z = z },
                                    { Pitch = 0, Yaw = 0, Roll = 0 })
if actor and actor:IsValid() then
  local tags = actor.Tags; tags[#tags + 1] = FName("MyCompanionTag")  -- Starfall tags everything it spawns
end
```

**B. Struct arguments as Lua tables to real Dragonwilds UFunctions.** RSE-Fixes `Scripts/server.lua`, a server-side mod (High that the call shape is accepted):

```lua
pawn:K2_SetActorLocation({ X = at.X, Y = at.Y, Z = z }, false, {}, true)  -- FVector, bSweep, out FHitResult, bTeleport
```

**C. Deferred spawn via GameplayStatics. UNTESTED.** Use this only if you need to set `AIControllerClass`/`AutoPossessAI` before `FinishSpawning`. Signature from UE (Med): `BeginDeferredActorSpawnFromClass(WorldContextObject, ActorClass, SpawnTransform, CollisionHandlingOverride, Owner, TransformScaleMethod)` and `FinishSpawningActor(Actor, SpawnTransform, TransformScaleMethod)`. The wrapper's own docs confirm these two are what `SpawnActor` calls. A maintainer comment on PR #864 says `FTransform` is Rotation (quaternion), Translation, Scale3D, and that the Lua table format for it is still undecided (Med). Expect to try `{Rotation={X=0,Y=0,Z=0,W=1}, Translation={X=,Y=,Z=}, Scale3D={X=1,Y=1,Z=1}}`:

```lua
local GS = StaticFindObject("/Script/Engine.Default__GameplayStatics")
local xf = { Rotation = {X=0,Y=0,Z=0,W=1}, Translation = {X=x,Y=y,Z=z}, Scale3D = {X=1,Y=1,Z=1} }
-- ESpawnActorCollisionHandlingMethod: 0 Undefined, 1 AlwaysSpawn, 2 AdjustIfPossibleButAlwaysSpawn,
-- 3 AdjustIfPossibleButDontSpawnIfColliding, 4 DontSpawnIfColliding  (Med: UE enum)
local pawn = GS:BeginDeferredActorSpawnFromClass(world, cls, xf, 2, nil, 0)
if pawn and pawn:IsValid() then
  pawn.AIControllerClass = aiControllerClass   -- TSubclassOf write from Lua: UNTESTED
  pawn.AutoPossessAI = 2                        -- EAutoPossessAI.Spawned
  GS:FinishSpawningActor(pawn, xf, 0)
end
```
The issue #527 workaround only calls Finish if Begin returned non-null (https://github.com/UE4SS-RE/RE-UE4SS/issues/527; Med). Unverified whether `nil` for `Owner` and the enum-as-integer work from Lua; if the call throws, read the Lua type stub for the exact parameter names.

**D. Rules from real Dragonwilds crashes** (devkit README, https://github.com/brucestarlove/Dragonwilds-UE4SS-AI-devkit, section "Rules learned the hard way"; High, they are first-hand):
- Run all Lua on the game thread from one timer. Do not use `LoopAsync`, `ExecuteAsync` or `ExecuteWithDelay`. Do not start `LoopInGameThreadWithDelay`/`ExecuteInGameThreadWithDelay` timers from inside another one.
- Hooks: read only `context:get()`; a handler's return value replaces the game function's return, so return nothing.
- `FindFirstOf`/`FindAllOf` are slow; cache.
- Always `IsValid()` before calling anything on an object you did not just create; `pcall` does not catch the crash.
- Never assign `FText` to a property or struct field (writes 24 bytes into 16). Pass FText only as a function argument.
- Gameplay actors bring their gameplay (damage, AI). Do not spawn a hostile "just to look".
- Characters are saved on each player's machine; never give a character an asset with no `PersistenceID`.

### 1.4 Real-mod search results (Palworld, Hogwarts Legacy, Satisfactory, Abiotic Factor, Grounded, Ready or Not, Motor Town)

I could not use GitHub code search (needs auth) and web search returned no repository that calls `:SpawnActor(` for those games. I did not find a usable example for any of them, so none is quoted. The working Lua examples above are all Dragonwilds-specific. If more are wanted, the main session can run `git`-clone-free searches later with an authenticated `gh search code "SpawnActor" --language lua`.

### 2.2 Calling them from UE4SS Lua (UNTESTED unless noted)

CDO and class paths follow the pattern UE4SS uses for GameplayStatics (`/Script/Engine.Default__GameplayStatics`, High, see 1.2) and Dragonwilds mods use for its own library (`/Script/Dominion.Default__AttributeFunctionLibrary`, High; trak3r `common/util.lua`). By the same pattern:

```lua
local AIH = StaticFindObject("/Script/AIModule.Default__AIBlueprintHelperLibrary")
local nav = StaticFindObject("/Script/NavigationSystem.Default__NavigationSystemV1")  -- see plan step 5

-- 1. Make sure the pawn has a controller.
local pawn = ...                       -- spawned Character
if not (pawn.Controller and pawn.Controller:IsValid()) then
  pawn:SpawnDefaultController()        -- uses pawn.AIControllerClass
end
local ctrl = pawn.Controller           -- validate with :IsValid() before use

-- 2. Move. Out parameters / return enum arrive as the return value or via a table in UE4SS 3.x.
local r = ctrl:MoveToLocation({X=tx,Y=ty,Z=tz}, 100.0, true, true, true, true, nil, true)
-- or follow a player pawn
local r2 = ctrl:MoveToActor(playerPawn, 200.0, true, true, true, nil, true)
-- or the simple form on any AController (it adds a PathFollowingComponent if missing)
AIH:SimpleMoveToLocation(ctrl, {X=tx,Y=ty,Z=tz})
```
Unverified details: whether `nil` is accepted for `TSubclassOf` parameters, and whether the return enum comes back as an integer. Read the generated Lua type stubs for the exact signature. In Dragonwilds mods, calling UFunctions uses `obj:Func(...)`; indexing a function name can produce a "TrivialObject" (trak3r `common/util.lua` comment, High).

`CreateMoveToProxyObject` returns a latent proxy that reports through delegates. Delegates are awkward from Lua and the devkit warns against many hooks, so **prefer polling**: re-issue `MoveToActor` on a slow event-driven timer and read `pawn:K2_GetActorLocation()` plus the PathFollowingComponent status.

### 2.3 Pitfalls (all Med unless noted)

- **Navmesh must cover both pawn and destination**, else `MoveToLocation`/`SimpleMoveToLocation` do nothing. Two separate Epic forum answers say this: https://forums.unrealengine.com/t/how-can-i-spawn-aicontroller-pawn-and-make-it-move/284432 (High that the advice is given).
- **Movement component.** The pawn needs a `UNavMovementComponent` (a `CharacterMovementComponent` qualifies), movement mode Walking or NavWalking, and `NavAgentProps` that match a supported agent in the RecastNavMesh. Mode numbers: 0 None, 1 Walking, 2 NavWalking, 3 Falling, 4 Swimming, 5 Flying, 6 Custom (RSE-Fixes `server.lua` uses this table; High).
- **World Partition and navmesh generation.** If Dragonwilds builds navmesh only around "navigation invokers" or streams nav data with cells, the server may have none near the companion. I found no public statement either way. Test (plan step 5). If missing: give the companion a `NavigationInvokerComponent` (Low: needs the component class to exist), or fall back to non-pathfinding movement (`bUsePathfinding=false`, straight line) or direct input (`pawn:AddMovementInput(dir, 1.0)` each tick), or last resort `K2_SetActorLocation` teleports (example B above).
- **Spawn timing.** A pawn's `BeginPlay` runs before its controller is possessed; code that needs the controller belongs in `PossessedBy`. Source: summary of https://answers.unrealengine.com/questions/705924/view.html (Low; secondary summary).
- **`SimpleMoveToLocation` and networking.** A 2014 blog says it was never meant for client-side use in multiplayer (http://drone-ah.com/2014/08/25/ue4-getting-multiplayer-player-pawn-ai-navigation-to-work-c/; Med). That is about a client pawn. Ours runs on the server, where AI controllers live, so it is fine.
- **Companion pattern.** The standard answer to "controlling a character with an AI controller from the player side" is: do not possess the player's pawn; spawn a separate AI-controlled character and send it commands. Source: https://forums.unrealengine.com/t/setting-up-aicontroller-on-player-character/225355 (High that this is the thread's advice). Matches our design.
- **Rotation.** An AI-controlled character may not rotate toward its move direction unless `bOrientRotationToMovement` or `bUseControllerDesiredRotation` is set on `CharacterMovement`. (Med; I found no web source, standard UE.)

### 2.4 Existing follower examples

Not tested in multiplayer." https://www.nexusmods.com/runescapedragonwilds/mods/703 (the page returned 403 to my fetcher; the description came from a search summary; Low). "Only you see" suggests a client-local actor, so it is not evidence for server replication.
- **Nexus "Dragon Mounts"** (mod 726): rideable mounts, experimental multiplayer. https://www.nexusmods.com/runescapedragonwilds/mods/726 (Low, search summary only). Dragonwilds has a native mount system (`UDominionMountComponent`, Starfall `DISCOVERY.md` line 42, High), but a mount is not an AI follower.

## 3. Approach (a) player-class pawn vs (b) existing NPC/creature class

### 3.1 Facts about Dragonwilds's player character

- Class `DominionPlayerCharacter` (`ADominionPlayerCharacter`, High; trak3r `util.lua` `isA(p,"DominionPlayerCharacter")`, RSE-Fixes `IsTeleporting()` comment). Blueprint name contains `BP_PlayerCharacter` (RSE-Toolbag `main.lua` line 179, High).
- **Inventory and other systems are components on the PlayerController, not the pawn.** `pc.BP_Components_Inventory`, `pc.BP_Components_InventoryController` (trak3r `util.lua`, `inventory.lua`; High). Starfall: `controller:GetInventory()`, `GetProgressComponent()`, `GetInventoryController()`, `GetPingComponent()`, `GetMapCustomizationComponent()` "all return components owned by the player's controller" (`DISCOVERY.md` line 119, High). Chat is a `PlayerChatComponent` on the controller too.
- Health and damage components are on the pawn (`pawn:GetBaseHealthComponent()`, `GetPlayerDamageComponent()`, trak3r GodMode; High). The pawn also has `CharacterMovement:FreezeCharacter`, `IsTeleporting`, `GetMountComponent` (High).
- Character data lives on each player's own machine: `Client_SaveToDisk`, `Server_ReceiveLoadFromDisk` (Starfall line 128, High). Identity and persistence key off `PlayerState:GetCharacterGuid()`.
- The server uses `PlayerController.Pawn` to find players (RSE-Fixes; High).

### 3.2 Known problems with a player-class pawn that has no PlayerController (general UE)

- `PlayerState` is null: "only exists for players, not NPCs". `AAIController::bWantsPlayerState` (C++ only, historically not Blueprint-exposed) gives a bot one. Sources: https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Engine/AController and forum threads https://answers.unrealengine.com/questions/242299/view.html, https://forums.unrealengine.com/questions/168533/how-can-i-have-proper-bot-players-with-a-playersta.html (Med; the fix reported as flaky in places).
- No HUD, no input component, no camera: harmless server-side.
- Possessing with an AIController breaks code that calls `GetController()` expecting a PlayerController. Epic thread above: the camera/reference breaks when an AIController possesses a player character (High that this is reported).
- Gameplay code that casts `GetController()` to `ADominionPlayerController` and then dereferences `GetInventory()` etc. will hit null. In native code this can crash the **server**, not just log an error. This is inference from where the components live (Med).
- Actions we want later (gather, craft, equip, attack with weapons) are driven through the controller-owned inventory and `Server_*` RPCs from the client (`Server_CraftRecipe`, `Server_RequestInteraction`, Starfall lines 122-123; High). A pawn with no controller has no equivalent entry point. We would be calling server-side internals directly.
- The player-count and join logic (session, EOS via Redpoint, player list) works on PlayerControllers/PlayerStates, so a controller-less pawn will not show as a player (Med/Low; inferred).
- Character appearance comes from the player's synced character data, so a bare spawn may look default or invisible (Low; unknown).

### 3.3 Approach (b) existing NPC/creature class

- Game NPC Blueprints exist and are `Character`-based: LiveMap scans `Character` instances and classifies `BP_NPC_*` as NPCs and the rest as creatures (https://github.com/weisuoyuzai/RSDragonwilds-LiveMap, `mod/LiveMap/Scripts/config.lua`, main.lua `scanCharacters`; Med). Creatures include chicken, cow, sheep, ram, deer, kebbit, wolf, goblins, terrorbird, raven, magpie and more (`data/Scripts/names.lua` `creatures`; High for names, but these are *name keys*, not class paths).
- Creatures already have AI controllers/behaviour trees and replicate as designed, so "spawn, possess, move, replicate" is the shortest path to the gate.
- Starfall proved a Blueprint NPC spawns and replicates by default (High) but with `bReplicateMovement=false` and `DORM_Initial`, so fix those.
- Downsides: hostile creatures will fight players unless faction/team or aggro is changed; passive animals (chicken, sheep, cow) are safe test bodies. A humanoid NPC (`BP_NPC_*` such as `BP_NPC_Death` or the vendor NPCs) looks right for a companion but may lack a movement-capable AI controller or a walking animation set (unknown). Gather/craft animations will not exist. For "plays like another player", this is a visual compromise.

### 3.4 Verdict

**(b) is more likely to work and should be tried first**, with a passive animal as the first test body, then a humanoid `BP_NPC_*`. Reasons: (1) no dependence on controller-owned components; (2) built-in AI hookup and replication paths; (3) the only public evidence of success in Dragonwilds is a spawned Blueprint NPC/actor. (a) is a stretch experiment: one throwaway spawn on a disposable world, watching for server errors. The CLAUDE.md gate allows either.

## 4. Replication requirements

### 4.1 Requirements for a server-spawned actor to appear on a vanilla client

- Spawn on the **server/authority**. A Lua mod on the dedicated server satisfies this. `World.AuthorityGameMode` is valid only on the host (Starfall line 36, High). Starfall's `HasAuthority` check is a good guard.
- `bReplicates` true on the class. Starfall probed: `BP_BaseInteractableNPC_C` and `DivineRock` replicate by default; `TargetPoint` and `PingActor` do not (`DISCOVERY.md` line 118, High). Read `bReplicates` as a property; `GetIsReplicated()` is not callable from Lua (Starfall line 127, High). Set with `SetReplicates(true)`.
- **Relevance.** Not `bAlwaysRelevant`; clients get the actor only inside `NetCullDistanceSquared` (225,000,000 = 150 m for the NPC class; High). Keep the companion within that range of Luis, or set `bAlwaysRelevant`. Starfall plans `bAlwaysRelevant = true` for its own carrier actor (`COOP.md` line 112, Low: planned, not confirmed).
- **Movement replication.** `bReplicateMovement` must be true for clients to see it move. The NPC class had it false (High). Call `SetReplicateMovement(true)`. Characters also need `CharacterMovement` replication, which comes with `bReplicates` for non-autonomous proxies (Med).
- **Dormancy.** `NetDormancy` 4 (`DORM_Initial`) on the NPC class (High). Epic: dormant actors are skipped until woken by `FlushNetDormancy`, `ForceNetUpdate` or `SetNetDormancy(DORM_Awake)`; `DORM_Initial` is meant for actors placed in the map. Source: https://dev.epicgames.com/documentation/en-us/unreal-engine/actor-network-dormancy-in-unreal-engine (Med). The Korean/Japanese pages say `FlushNetDormancy` on a `DORM_Initial` actor makes it `DORM_DormantAll`, which is not what you want; set `DORM_Awake` (value 1) instead, as the DivineRock has (High for the value; Low for the translation claim). A runtime-spawned dormant-initial actor may never reach clients: treat as a likely cause if "server sees it, Luis does not".
- **Push model.** The project enables it. Push-model properties are only sent when the C++ setter marks them dirty (`MARK_PROPERTY_DIRTY_FROM_NAME`). UE4SS Lua property writes go straight to memory and do not mark dirty. I found no source stating this directly (Low). Epic bug UE-226689 says some Blueprint variable-set nodes also fail to mark dirty (https://issues.unrealengine.com/issue/UE-226689; Med). Practical rule: **change replicated state through UFunction setters** (`SetReplicates`, `SetReplicateMovement`, `SetNetDormancy`, `SetOwner`, `SetActorScale3D`, `K2_SetActorLocation`, `ForceNetUpdate`), not by assigning properties. Non-replicated flags such as `bSkipSpudStore` are safe to assign (Starfall did).
- **Replication system.** The build ships both `ReplicationGraph` and `IrisCore`; which is active is unknown (Starfall line 127, High). Iris has its own dormancy flush quirks (UE-365983, https://issues.unrealengine.com/issue/UE-365983; Med).
- Components added at run time replicate only if `SetIsReplicated(true)` is called, and are not nameable across the network otherwise (Starfall line 118; expected from the engine, not tested).
- Starfall states that "whether an actor made to replicate reaches a joiner" is still open for its mod (`COOP.md`). So even the rock case has not been confirmed with a remote client. That is our step S1.

### 4.2 What breaks when a client rejoins (all Med/Low; engine behaviour, none Dragonwilds-verified)

- A rejoin is a new net connection. The server opens a fresh actor channel for each relevant replicated actor, so a normally replicating companion reappears. A `DORM_Initial` or dormant actor may not. Wake it, or `ForceNetUpdate()` after the join.
- The companion must still exist on the server. The server holds `FindAllOf` handles; revalidate after map change (RSE-Fixes drops all handles on map load: "the old world is being destroyed", High).
- **Save-file persistence.** Dragonwilds uses SPUD-style world saves: `AWorldActor` has `bSkipSpudStore`, `bRegisterAsRuntimeSpawned`, `SpudGuid`; `UPersistenceSubsystem:SaveGame(false)` forces a save (Starfall line 34, High). Starfall found a spawned rock was **not** written to the save, even with the flag off (High for rocks; Low for creatures). If a spawned NPC *is* saved, it will duplicate or resurrect on restart. Tag the companion, set `bSkipSpudStore = true` if the class has it, and on mod start delete any tagged leftovers (Starfall `World.destroyTagged`, High).
- Players arriving have had server-side "fall through buildings" issues, handled by RSE-Fixes with `FreezeCharacter`. Unrelated to our actor but shows the server position of arrivals can lag world streaming (https://github.com/kevinw9092/RSE-Fixes, `Scripts/server.lua`; Med).

## 5. Dragonwilds-specific findings

### 5.1 Classes and names seen in public mod source (all High, from the repos named)

- Module: `/Script/Dominion.*`. Seen: `DominionPlayerCharacter`, `DominionPlayerController`, `InteractableNPC` (not spawnable natively), `WorldActor`, `AttributeFunctionLibrary`, `PersistenceSubsystem`, `InventoryController`, `CraftingStationComponent`, `InteractionComponent`, `SignComponent`, `ResourceRespawnComponent`, `DominionMountComponent`, `DominionCheatManager`. Sources: Starfall `DISCOVERY.md`; trak3r `common/util.lua`; RSE-Toolbag `Scripts/main.lua`.
- Other modules: `/Script/MinimapPlugin.MapIconComponent`, `JagexChatBackend` (chat), game features such as `/UmbralSands`, `/ScornedWilderness`.
- Chat exists: `PlayerChatComponent` with `Server_SendChatMessage(FChatMessageData, FChatPlayerFilterData)`, `Client_ReceiveChatMessage`; `GetPlayerChatComponent()` returns it; `bReplicates` false on that component; `IsChatEnabled()` was false in solo (Starfall lines 119 and 125, High). Relevant to Phase 2 and to speech output later. Note for Phase 5/6, not Phase 4.
- Creature journal names list (LiveMap `names.lua`): AbyssalDemon, Chicken, Cow, Deer, Kebbit, Magpie, Raven, Ram, Sheep, Wolf, WolfElite, TerrorBird, MeleeGoblin, RangedGoblin, RuntGoblin, ShieldGoblin, GiantRat, FungalRat, MediumBeast, ThaneBeast, TrainingDummy and more. The `ainames` table lists AI display names (e.g. `AggressiveTerrorBird`, `Aberforth`, `BlackKnight1HMelee`, `BlackDragon`). These are names, not class paths. Use the dump to get real class paths.
- AI-related native class names (AIController subclass, behaviour trees, faction) are **not** in any public source I read. The dump must supply them.

### 5.2 Spawn commands, cheats, console

- **No built-in console.** "RuneScape Dragonwilds does not have native console commands or a built-in console"; players use SML for one (`~` or backtick). No spawn command is documented; "item spawning requires a separate compatible mod". Source: https://help.sparkedhost.com/en/article/all-runescape-dragonwilds-console-commands-1hxkam/ (Med; hosting-company help page).
- **`UDominionCheatManager`** exists with `domSetTime`, `domAddItem` and many more, **but they are empty in the shipped game** (Starfall `DISCOVERY.md` line 52 and devkit README rule 7; High). So a CheatManager route is a dead end for spawning, unless the *engine's* generic `UCheatManager::Summon(ClassName)` is still present. That function exists in stock UE (issue #527 shows `summon` working in a UE5.1 game; Med). Whether Dragonwilds's shipping build keeps it, and whether a CheatManager can be constructed on a PlayerController on the server, is unknown. UE4SS's bundled mods list a CheatManagerEnabler (https://deepwiki.com/UE4SS-RE/RE-UE4SS/5.6-bundled-lua-mods-and-shared-libraries; Low, listing only). It is a cheap experiment (plan S3b), but expect it to spawn at the controller's view point and to need an in-world pawn, so it is awkward for a controllerless server.
- **No Nexus RSE-* mod spawns creatures.** I cloned and grepped `kevinw9092/RSE-Server`, `RSE-Toolbag`, `RSE-Fixes`. No actor spawning (only "respawn" of resource components and building-piece spawn queues). RSE-Server is a Docker/Wine runner for the Windows dedicated server (High). Nothing public matches "mod that spawns creatures".
- The `trak3r/dragonwilds` mods (sort into chests, auto-eat, god mode) and `KylerN45/DragonwildsMods` are QoL mods; no spawning (High for trak3r; KylerN45 not read).

### 5.3 Server and UE4SS facts that affect the plan

- Windows dedicated server binary: `Binaries/Win64/RSDragonwildsServer-Win64-Shipping.exe`. RSE-Server runs it directly, because "Unreal's small `RSDragonwildsServer.exe` launcher never starts the server under Wine" (README of https://github.com/kevinw9092/RSE-Server; High, Wine only).
- UE4SS loader name: RSE-Server renames `dwmapi.dll` to `version.dll` because "the dedicated server never loads `dwmapi` (it has no desktop window manager), but it does load `VERSION.dll`" (High for Wine). Hosting guides use `dwmapi.dll` on Windows (https://www.survivalservers.com/wiki/How_to_Install_Mods_on_a_RuneScape_Dragonwild_Server; Med). On our Windows Server VM, try `dwmapi.dll` first; if UE4SS does not load, use `version.dll`. This belongs to Phase 2, noted here because it may bite Phase 4.
- Official Linux image `ghcr.io/runescape/rsdw-dedicated` runs the Linux build, which UE4SS cannot load into (RSE-Server README; High). Shockbyte "Modded" type switches to the Windows build with UE4SS (https://shockbyte.com/help/knowledgebase/articles/how-to-add-mods-to-your-runescape-dragonwilds-server; Med).
- The game logs a `LogModDetection` warning listing `dwmapi.dll` and `ue4ss/UE4SS.dll` as "unexpected files, which suggests mod use". Nothing else came of it (Starfall `DISCOVERY.md` line 62, High).
- Dragonwilds 1.0 shipped 15 Sep 2026 per one source; mods "may break" after 1.0 (https://www.survivalservers.com/wiki/RuneScape_Dragonwilds_Mods_After_the_1.0_Update; Low, title only). Record our build ID.
- Starfall's author warns that probes crashed the game several times and "one left a character unable to load." Use a throwaway world and character (matches CLAUDE.md).

## 6. Experiment plan for the main session

Preconditions: server runs with UE4SS, reflection dump generated (`CXXHeaderDump`, Lua types, `UE4SS_ObjectDump.txt`), a mod that logs to a file. Use a throwaway world. Record every result in `docs/DISCOVERIES.md`. Ask Luis only yes/no visual questions. Each step has a stop/continue rule.

Lua habits for all steps: game thread only, `IsValid()` before every call, `pcall` around experiments, write step names to a trace file before each risky call (so a crash names the step), tag spawned actors, and keep handles.

Dump files to grep: `H` = `CXXHeaderDump/**`, `O` = `UE4SS_ObjectDump.txt`, `T` = Lua types.

**S0. World handle on a headless server.**
- Grep: `O`: `GameInstance`, `DominionGameInstance`, `GameModeBase`, `DominionGameMode`, `/Game/Maps/World/L_World`; `H`: `class UDominionGameInstance`, `AuthorityGameMode`.
- Test: from a timer, try `FindFirstOf("GameInstance")`, then `:GetWorld()`, with `FindAllOf("PlayerController")` as the fallback once Luis is connected. Log `world:GetFullName()` and whether `IsServer`/`IsDedicatedServer` read true/true (`/Script/Engine.Default__KismetSystemLibrary`).
- Pass: valid world and `IsDedicatedServer` true.

**S1. Replication sanity check with a known-good actor (rock).** *Do this before any AI work.*
- Grep: `O`: `BP_DivineRock_Iron`, `DivineRock`.
- Test: spawn `BP_DivineRock_Iron_C` 5 m in front of Luis (position from `FindAllOf("PlayerController")` → `.Pawn:K2_GetActorLocation()`), using snippet A. Log `bReplicates`, `bReplicateMovement`, `NetDormancy`, `NetCullDistanceSquared`, `bAlwaysRelevant`.
- Ask Luis: "Do you see a glowing/divine rock about 5 m in front of you? Yes/No, anything odd?" Then ask him to leave and rejoin and ask again.
- Pass: Luis sees it, still sees it after rejoin. This proves the spawn path and replication to a vanilla GFN client. If it fails, stop and fix before S2.

**S2. Inventory of candidate body classes.**
- Grep `O`: `BP_NPC_`, `Class /Game/Gameplay/NPCs`, `/Game/Gameplay/Creatures`, `/Game/Gameplay/Enemies`, `/Game/Gameplay/AI`, `BP_Chicken`, `BP_Sheep`, `BP_Cow`, `BP_Deer`, `BP_Ram`, `BP_Kebbit`, `BP_Wolf`, `BP_Goblin`, `BP_TerrorBird`, `BP_TrainingDummy`.
- Grep `H`: `: public ACharacter`, `: public APawn`, `ADominionCharacter`, `ADominionNPC`, `ADominionAICharacter`, `ADominionCreature`, `ADominionAIController`, `AAIController`, `AIControllerClass`, `AutoPossessAI`, `BehaviorTree`, `Blackboard`.
- Companion/pet-like systems: grep `Companion`, `Pet`, `Follower`, `Familiar`, `Summon`, `Minion`, `Ally`, `Tame`, `Mount`, `Hireling`, `Escort`, `Villager`.
- Output: a short table of 3 to 5 candidates: class path, parent class, whether it derives from `ACharacter`, default `AIControllerClass`, whether passive.
- Prefer: a passive animal (chicken/sheep/cow) first, a humanoid `BP_NPC_*` second.

**S3. Read the candidate's defaults (no spawn yet if possible).**
- Test: on the class default object (`Default__<ClassName>`), log `AIControllerClass`, `AutoPossessAI`, `bReplicates`, `bReplicateMovement`, `NetDormancy`, `NetCullDistanceSquared`, `bAlwaysRelevant`, `CharacterMovement.MovementMode`, `CharacterMovement.DefaultLandMovementMode`, `NavAgentProps`, `bOrientRotationToMovement`, `bSkipSpudStore`.
- Grep `H` for faction and aggro on that class: `Faction`, `Team`, `GenericTeamAgent`, `Hostile`, `Aggro`, `Perception`, `Threat`, `TargetingComponent`.
- **S3b (optional, cheap).** Find whether engine `Summon` survives: grep `T`/`H` for `CheatManager`, `Summon`, `EnableCheats`, `ProcessConsoleExec`. Do not spend long here.

**S4. Spawn the candidate and see what it does by default.**
- Test: spawn the S2 passive candidate 6 m from Luis with snippet A. Immediately log `pawn.Controller` (valid? class?), `GetClass():GetFullName()`, and the S3 fields. If the controller is null, call `pawn:SpawnDefaultController()` and log again.
- Hook for evidence (read `context:get()` only): `/Script/Engine.Controller:Possess`, `/Script/Engine.Pawn:ReceivePossessed`.
- Ask Luis: "Do you see a <sheep/chicken> 6 m ahead? Is it moving by itself? Yes/No".
- Pass: pawn exists, has a valid AIController, Luis sees it.

**S5. Navmesh presence (the key unknown).**
- Grep `O`: `RecastNavMesh`, `NavigationSystemV1`, `NavMeshBoundsVolume`, `NavModifierVolume`, `NavigationInvoker`, `NavigationData`. Grep `H`: `NavigationInvokerComponent`, `bGenerateNavigationOnlyAroundNavigationInvokers`, `RuntimeGeneration`, `NavigationDataChunk`.
- Test: `FindAllOf("RecastNavMesh")` (the dump says one exists in `L_World`); log count and full name. Then call the `NavigationSystemV1` function that projects a point onto the navmesh (grep `H`/`T` for `K2_ProjectPointToNavigation`, `GetRandomReachablePointInRadius`, `K2_GetRandomReachablePointInRadius`, `IsNavigationBeingBuilt`, `GetNavigationSystem`) at the companion's location, at Luis's location, and at 3 points 20 m away. Log hit/miss.
- Interpretation: hits near both Luis and the pawn means pathfinding can work. Misses near the pawn but hits near Luis mean navmesh is invoker- or stream-limited: add an invoker component (S6 fallback) or use straight-line movement. Misses everywhere mean the dedicated server has no navmesh; use direct input.
- Pass: projection hits within 100 m of Luis.

**S6. Move to a point.**
- Grep `T`/`H`: `MoveToLocation`, `MoveToActor`, `SimpleMoveToLocation`, `ReceiveMoveCompleted`, `PathFollowingComponent`, `GetPathFollowingComponent`, `GetMoveStatus`, `StopMovement`, `AbortMove`, `EPathFollowingRequestResult`, `EPathFollowingStatus`.
- Test, in order, stopping at the first that moves the pawn: (1) `ctrl:MoveToLocation(target, 100, true, true, true, true, nil, true)` with target 10 m away; log the return value; poll `K2_GetActorLocation()` every 0.5 s for 10 s. (2) `AIH:SimpleMoveToLocation(ctrl, target)`. (3) `bUsePathfinding=false` variant. (4) `pawn:AddMovementInput(dir, 1.0, false)` every tick-timer step (needs `CharacterMovement.MovementMode = 1`).
- Evidence: location change; `GetMoveStatus`; log which variant worked. Ask Luis: "Does it walk smoothly or teleport/jitter? smooth / jitter / not moving".
- Pass: pawn reaches target on at least one variant, and Luis sees it moving.

**S7. Replication of motion.**
- Grep `T`/`H`: `SetReplicateMovement`, `SetNetDormancy`, `FlushNetDormancy`, `ForceNetUpdate`, `SetReplicates`, `SetOwner`, `NetUpdateFrequency`, `SetNetUpdateFrequency`.
- If Luis sees it spawn but not move (or sees it frozen at the spawn point), call `SetReplicateMovement(true)`, `SetNetDormancy(1)`, `ForceNetUpdate()` on the pawn, and re-test. Log before/after values. Record which fix was needed.
- Pass: Luis sees motion and it matches the server log.

**S8. Follow loop.**
- Test: every 1 s (timer, not per tick), `ctrl:MoveToActor(playerPawn, 250, true, true, true, nil, true)` if the status is idle; log distance. Stop when within 300 cm. Walk Luis 50 m away, then back. Test fall-behind recovery with a teleport fallback (`K2_SetActorLocation`) if the distance exceeds ~50 m.
- Ask Luis: "Does it follow you and stop near you, no spinning/sliding? Yes/No".
- Pass: follows through at least 100 m of walking including slopes.

**S9. Rejoin and restart robustness.**
- Test: Luis disconnects and reconnects; ask "Is it still visible and where you left it? Yes/No". Then restart the server: `FindAllOf` for the tag must find zero or one companion (no duplicates). Set `bSkipSpudStore = true` and re-run. Force a save (`PersistenceSubsystem:SaveGame(false)`, Starfall) and search the save for the class name (Starfall method: class names are plain text in the `.sav`).
- Pass: visible after rejoin, no duplicates after restart.
- Also: despawn on mod load via tagged-actor cleanup.

**S10. Gate decision for (b).** If S1 to S9 pass, the Phase 4 gate is met with an NPC body. Write the DISCOVERIES entry and stop. If S6 or S5 fail only because of navmesh, report to Luis with evidence and the options in 2.3 before declaring a kill.

**S11. Approach (a), stretch only, on a disposable character.**
- Grep `O`: `BP_PlayerCharacter`, `DominionPlayerCharacter`, `BP_PlayerController`, `BP_PlayerState`, `DominionPlayerState`, `DominionGameMode`, `SpawnDefaultPawnFor`, `RestartPlayer`, `HandleStartingNewPlayer`. Grep `H`: `class ADominionPlayerCharacter`, `GetController`, `Cast<ADominionPlayerController>`, `GetInventory`.
- Test: spawn the player-character Blueprint class (path from `O`) 10 m from Luis with trace logging. Log `pawn.Controller`, `pawn.PlayerState`, components present (`BP_Components_*`), and the first 30 s of server log for errors. Then `SpawnDefaultController` with an `AIController`. Try S6 movement.
- Stop on any server crash and report. Note for the log: after a crash, restart the server and check the world save and character files before the next try (devkit README rule 14).

**Logging for each step.** One trace line before the risky call and one after: `step, time, class, IsValid, key fields`. Write to a file the main session can read without asking Luis to paste logs (CLAUDE.md rule).
