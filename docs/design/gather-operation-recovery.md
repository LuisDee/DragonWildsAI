# Gathering operation and material contracts (2026-10-27)

## Goal
For an operation request, the companion selects and performs the requested kind of work, discovers missing prerequisites, and reports failure if it cannot verify the work. For a material request, it can still collect an equivalent item from an accessible source. The observed no-axe run is a false completion: `gather` collected the same item from sticks with zero swings, hits and breaks, while Woodcutting XP stayed at 206; an inventory gain alone did not establish a felled tree.

## Approach: Phase A (approved for implementation)

Expose an optional model-selected acquisition mode from existing profile data. Omission preserves material acquisition and its tool-free same-item fallback. A constrained mode filters exact, alias, item and category candidates before selection; an unavailable matching tool gives a truthful failure rather than switching modes. The handler passes the choice through, and the manifest describes it. Count always means additional inventory items, never root or work units. Report selected profile, mode and fallback; these are selection metadata, not proof of physical provenance. Distinguish expected profile training from observed XP. The loop can still collect nearby existing item drops even with a constrained profile; the selection does not prove a tree fell.

Generic Director guidance distinguishes possession from requested work and asks the model to choose appropriate existing evidence. Code does not interpret the player's wording or veto its choices; inventory-only success can still produce false completion and negative controls must flag it. Files: `client_mod/scripts/gather.lua`, `client_mod/scripts/gather_profiles.lua` if needed, `brain/director.py`, `brain/interface.py` (typed argument normalization), and focused gather/Director/capability tests. No judge edits.

Phase B is deferred until native observations establish how to verify a matching root transition. Existing `broken` can include children and pickups; disappearance alone is insufficient and XP is corroboration, not target proof. Do not implement root counting now. The model composes prerequisites using existing crafting and equipment tools.

## Alternatives and principles
Removing fallback globally breaks legitimate bootstrap/material tasks. Merely adding `source` to the result is already insufficient in the observed run. Requiring XP for all gathering excludes valid pickup and does not establish a particular target; a new frozen predicate or a deterministic text-based veto breaches the current boundaries. A full planning framework is unnecessary. This design preserves real player paths, model interpretation, generic profiles, truthful failures and verified state. It introduces no fixed item lists or benchmark sequence. A fresh-context PRINCIPLES review is required before implementation; any required judge modification is separately blocked pending Luis's approval.

## Acceptance test
Offline: profile-generated alternatives for several materials; constrained mode filters exact, alias, item and category candidates before selection and fails with a specific tool/tier reason rather than substituting. Counts remain additional inventory items in every mode. Test material-only fallback remains usable, profile selection and unknown training accurately reported, and schema/result reaches the model. Include negative controls for claims-only and pickup-only inventory gains, and held-out gathering/mining variants that share an item but differ in operation. Verify absent/unknown XP never passes an XP predicate; no judge edits.

Dev scenario and live: reserve the one client, confirm dev target and forbidden Shockbyte, and use the queue and budget rules. On current code with the same no-axe request, independently capture planner decisions, prerequisites, real client actions and before/after game evidence: actual tree state transition and corresponding skill XP, not only the inventory delta or model claim. Count bench/craft/equip actions only if actually observed; no harness grant of the outcome or scripted plan. Include material-only pickup and a different operation/mining case, with negative controls. A model choosing an inventory-only success condition, or missing reliable root evidence, is a failed measurement, not a success. Report the current-code hash, models/call counts/spend and constraints; do not claim broad generalisation from a single run.

### Gather adapter contract repair (2026-10-27)

The live executor validated the new optional `mode` but the bridge adapter still rejected the keyword before sending a command. Append the optional parameter after existing positional parameters in the game interface and bridge adapter, and reuse `_drop_none` to omit absent values from the transport. Mock adapters accept the same signature and explicitly report unsupported constrained selection rather than pretending to implement it. This is general contract propagation; it does not choose modes or change game mechanics. The real Executor, typed validation, bridge transport and Lua harness must be tested together for explicit and omitted mode; the Lua fake may truthfully return unsupported while the captured command proves delivery.

Supplementary search: repository `brain/interface.py`, `brain/executor.py`, `brain/bridge_client.py`, mock gather implementations, bridge harness, plus earlier searches above. Web queries: `site:docs.python.org inspect Signature bind TypeError unexpected keyword argument function parameters`; `Pydantic model_dump serialization`; `site:docs.python.org optional keyword argument defaults function parameters keyword forwarding`; `site:docs.python.org json encode optional None dict serialization`. Opened [Python signature binding](https://docs.python.org/3.12/library/inspect.html#inspect.Signature.bind), [Pydantic serialization](https://docs.pydantic.dev/latest/concepts/serialization/), and [Python default and keyword arguments](https://docs.python.org/3/tutorial/controlflow.html#default-argument-values). These document argument binding and serialization, not Dragonwilds semantics. Decision: **reuse** typed validation, named optional parameters and existing `_drop_none` rather than generic keyword swallowing or a new transport. Existing Phase A principles and real-world acceptance remain unchanged.
