# Live DEV control validation (2026-10-28)

## Goal

Produce inspectable, current-code positive and negative control evidence for the frozen case predicates on the single DEV client. A control is a developer-driven diagnostic, not an autonomous companion pass. This is a proposal for independent review before implementation; no live run or validity certification is claimed here.

## Approach

Proposed outside frozen judge paths: `tools/dev_controls.py` and `tests/test_dev_controls.py`. Reuse `spec.load_cases`, `spec.case_hash`, `runner.entry_hash`, `hashes.validity_key`, `agents.bind`, `ObservedGame`, `DevTarget`, and `devrun.judge_dev`. Do not edit `evals/bench`, `brain/predicates.py`, target definitions, fixtures or probes. `runner controls` is mock lint only; `agents.run_script` uses mock `world.tick`/`world.ground`, silently ignores unknown steps, and `control_steps` selects the mock oracle. It is not a live runner. `judge_dev` supplies the actual frozen result; its error, unverifiable and guard failure are not interchangeable with a demonstrated negative `not_achieved`.

1. The operator selects an exact case and control, on the deployed tested tree, through the existing live-check queue and exclusive reservation. Preflight records operator, run UUID, current deployed commit/dirty state and byte identity, case/scorer/body/entry hashes, catalog build, actual client build and process/bridge identity, DEV endpoint, forbidden-address check, ClaudeDev GUID/name, world identity, existing slot/lease ownership and backup references. Reject unknown, stale, mismatched, dirty or unverified identity; verify no competing brain/action and sufficient resource headroom. Preserve all per-world memories, saves and client state; back them up before any relevant setup. Never switch/create a character, restore/reset a world or start another server/client. A snapshot or `character` requirement that cannot be verified in the present world is blocked; never apply `CharacterSwitch` or silently treat it as satisfied. A nonempty snapshot is a prerequisite to verify, not authorization to restore it.
2. Validate the entire script and fixture plan before any effect. Positive uses only executable `case.oracle.dev` list steps; a `scripted:<file>` without a separately reviewed, supported implementation, prose/notes, missing/empty oracle, unknown shape or unbound variable is blocked, never passed. Negative controls use explicit frozen scripts for `wrong_action`, `alt_means`, `partial`; `do_nothing` waits the full real case wall window with ambient/reflex behavior recorded, and `claims_only` says a claim through the game interface without model calls. Do not derive `partial` from an oracle implicitly. Frozen explicit `controls.na` with a substantive reason is the only possible N/A source; record the exact case-provided reason and never infer N/A from a missing/unsupported script. N/A is subject to fresh reviewer approval of applicability; until then block promotion. Do not accept imported verdicts or arbitrary external script files.
3. Implement a small strict interpreter, separate from the companion: accept only validated `tool`, `say`, bounded real-time `wait_s`, and explicitly supported fixture `setup` steps. Bind setup outputs with `agents.bind`; unresolved bindings and ambiguous/multiple step keys stop. Reject `pickup_all` and any mock-only/unknown operation until there is a reviewed native meaning. `tool` calls go through the observed real client bridge. Harness setup is distinct, logged and limited to approved DEV fixtures, with no invented results; generic test data may name an item or action, but no item/phrase policy enters companion code. Verify `fixtures.requires` against fresh evidence using existing predicates; missing evidence is blocked. Cases that require unsupported setup or world state remain blocked.
4. Execute each control in its own independently checked scenario and record setup, state and assistance; never assume a previous control leaves the required baseline. `ObservedGame.start/finish` and observations capture probes, tool replies and referee events; store original raw command responses, before/after probes, events, bindings, action attempts, timestamps, setup and resulting judge detail/missing/mismatches in a unique run directory under ignored `logs/`. Preserve partial records even on interruption. Model speech/claims never supply game-state evidence. Probes and supported referee events are evidence; errors or absent data fail closed. Capture action intent before dispatch because `ObservedGame` appends an observation only after the call and probes return. Judge once with the unchanged `judge_dev` after a valid completed observation, and retain its unmodified result and reason. Positive requires `pass`; a negative requires `fail` because the success predicate was not achieved, not a broken guard, missing sensor, timeout or infrastructure error. Confirm do-nothing actually ran its whole window; a setup that accidentally achieves the predicate invalidates its control.
5. Guard at each effectful boundary, including nested fixture/body calls, referee start/stop, waits and every client action: same reservation owner/token, current DEV endpoint and explicit forbidden target set, ClaudeDev/world identity, process/bridge generation, no competing brain or action, active lease, deadline and cancellation state. Existing `DevTarget.guard` checks local/forbidden endpoint and brain but does not itself establish slot, character, bridge or every nested call; compose it with the additional checks at the transport boundary, and refuse any operation that cannot be guarded there. Do not infer that a local address alone identifies the intended server. Use only current owner-aware cleanup: stop only owned referee/action where identity and completion are established. Unknown in-flight state means hold the slot and report blocked for operator recovery, never reload the bridge, release it as idle, or stop another owner's work.
6. Deadlines bound script, case and parent watchdog. The parent observes a child process and records timeout/crash; a Python timeout does not cancel a dispatched game action. If a child must be terminated, first request a supported cooperative stop, verify the owned action actually ended and probe state; if that cannot be established, retain reservation/hold and escalate recovery, not fake cancellation or kill the game/server. Do not schedule the next case until quiescence is verified. Persist active and blocked durations/reasons and next relevant unmet case.
7. Write an immutable, content-addressed raw evidence bundle per control with provenance and integrity hashes, including incomplete failures; never mutate it. Construct any aggregate validity record only from this runner's complete, independently verified bundles with the same case/scorer/body/catalog-build/entry and compatible runtime identity, explicit N/A decisions and required controls. Recompute hashes and require `oracle=pass` and each applicable negative=`fail`, with no imported outcomes. Stage a new file and use existing `brain.fileio.atomic_write` for an index only after validating completeness and collision handling; do not overwrite an existing valid record or pretend Python's POSIX atomicity guarantee proves Windows crash durability. Archive older material, not replace it silently. `goal_check.case_valid` accepts `target`, `controls`, `na` and uses a key from case/scorer/body/catalog build/entry; its permissive `na` and lack of actual-client-build checks mean the new writer must enforce these stronger conditions itself.

The observed client build **26162923** and catalog build **26161880** are different (repository discovery dated 2026-10-26), so store both as separate facts and **block writing/promoting an official `logs/evals/validity/<key>.json` certification** while they differ or either is unknown. Diagnostic bundles may still be collected with the mismatch clearly marked. A later user-approved resolution and fresh evidence are required; never label the catalog number as the actual client build. `goal_check` itself cannot enforce that extra condition without a frozen-judge change, which this design does not request.

## Initial diagnostic implementation and limits

The first implementation supports only tracked frozen case files and list scripts with body tools, speech and bounded waits, and `unlock`/`grant_runes` setup. Unsupported snapshots, scene/character/requirement features, mock steps and scripts with missing concrete bindings are blocked. It validates the whole grammar and declared binding names before setup, then concrete arguments before action. `claims_only` says the claim; the mock's `remember` operation is not a native client action and is deliberately absent. N/A is retained in metadata only. The runner never writes or promotes official validity, even if builds match. It keeps an append-only diagnostic journal and attributes this to the external operator.

Live invocation is allowed only from the deployed checkout with an explicitly owned slot and independently monitoring operator; it verifies the existing publication's recorded changed-code bytes and clean tracked deployment, client watchdog build/PID/process start, ClaudeDev/pawn/world, bridge generation, local DEV endpoint plus forbidden set and full idle status. Guarded nested DEV transports record raw responses. The operator remains responsible for the parent watchdog, maintaining the lease and recovery; a timeout is not cancellation, the runner never stops a potentially foreign action, releases the slot or implicitly stops the referee. The owner must inspect/recover the owned referee and verify true idle. The publication manifest checks the code paths recorded by that publication plus the clean deployed Git tree; it is not a complete attestation of every loaded module. The whole design still requires cold review and fresh offline then developer-driven DEV validation. These diagnostics do not establish live readiness or a goal pass.

`--backup` names a JSON manifest in `logs/recovery/`, prepared by the operator from actual copies before setup: `{"world":"<expected-world>","character":"ClaudeDev","files":[{"category":"world_state|skills|envelopes|client_state|world_save","source":"<original path>","copy":"<relative copied file>","sha256":"<64 hex>"}]}`. Each listed entry uses one category (the vertical bars above enumerate options); all five categories are required. State and skills source paths must identify the selected world; envelope/client paths must be in their corresponding existing directories; save source must name a save path. Every copied file must remain under the manifest directory and match its SHA-256. Record manifest digest and category coverage after fresh world/character admission, before any fixture. This attests copied files and stated identity, not that an actively written save remains byte-identical or that one file represents every relevant file; the operator remains responsible for complete preservation. No restoration occurs. A final guard immediately at `call` or `say` dispatch closes the interval after the observer's pre-action probe; a failed or ambiguous guard retains the slot.

## Generality and principles

Control steps are benchmark data used only by the harness; they never direct or modify model decisions. Real client input and read-only probe/referee evidence remain the scoring path. DEV-only fixture grants/spawns are harness assistance and are logged, never companion outcomes. Preserve one voice, one operator and persistent per-world learning; every unsafe/unknown state reports a specific block. No exception to PRINCIPLES is requested. Script validity does not establish that a case is feasible or its controls are comprehensive, and no diagnostic counts toward M1–M6 autonomy.

## Acceptance tests

- Offline, fake transports and deterministic clock: exact DEV oracle and negative scripts use native observed calls, binding and frozen `judge_dev`; unknown/notes-only/scripted-file/multiple-key/mock-only steps, absent requirements or unbound variables abort before any action. Assert do-nothing spans the full wall window and claims cannot manufacture success. Assert baseline independently checked for every control, and fixture/setup attribution preserved.
- Inject forbidden/nonlocal/wrong DEV endpoint, wrong ClaudeDev GUID, changed bridge/process, stale lease, competing operator/brain, busy or unknown action before each nested transport call, including cleanup: no subsequent effect; never stop another owner's referee or release a busy slot. Timeout/crash/in-flight tests retain partial evidence and hold ownership until real quiescence; never report a killed worker as cancelled game work.
- Verify lossless raw evidence and hashes, both builds, immutable unique bundles, mismatches and missing probes. Reject malformed or altered evidence, different key/identity, mock data, fabricated imported results, missing controls, unsupported controls, empty N/A reasons and unreviewed N/A. Guard failures, sensor mismatch, errors, timeouts and unverifiable results are not negative passes. Simulate interrupted writes and collision; no partial or overwritten official record. Explicitly prove 26162923 vs 26161880 and unknown builds cannot promote, even if all controls otherwise satisfy frozen `case_valid`; matching builds alone do not bypass the other checks.
- Run focused regressions and `tests/test_design_notes.py` first. Fresh independent design and code reviews, then full gate as scheduled. On the tested deployment, the single operator selects a supported, currently unmet case; record setup and developer driver, run positive then applicable negatives through real client controls, checking world preconditions and idle/ownership at each boundary. Block unsupported cases and build mismatch with evidence. Only after that developer diagnostic, independently run the unassisted Haiku deployment-model test; no prior assistance becomes an autonomous pass. Re-measure goal targets only with approved current-code evidence.

## Root reviewer checklist

- Verify script grammar and `case_valid` schema against frozen source, and that the interpreter can cover a real supported case without editing a judge or silently accepting mock semantics.
- Audit every nested transport and cleanup path for the same guard, actual ownership and timebound; verify unknown in-flight state cannot release the slot. Confirm identity/build attestation has a real source, not a catalog guess.
- Verify preconditions and no character/snapshot restoration, baseline contamination or hidden N/A inference. Check that raw files and hashes are generated from actual calls, retained on all failure paths, and that no arbitrary result can enter certification.
- Review Windows publication/collision handling and actual tested deployment provenance. Confirm mismatch blocks official promotion and that current frozen `case_valid` does not enforce it independently.
