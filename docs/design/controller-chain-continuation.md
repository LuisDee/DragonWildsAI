# Bounded continuation after a controller chain yield

## Goal and evidence

Keep a direct multi-step request from silently disappearing solely because its current controller slice reached its limit. On deployed 528ae99, the 2026-10-27 survival diagnostic gathered and consumed berries, then logged `chain_stopped turns=4 why=budget` without a final model response, queued goal, or water/rest. The private diagnostic then exited without another pump. This proves an incomplete finite chain in that run; a continuously running production agent's subsequent event-driven behavior was not measured. `MAX_TURNS=4` means the initial action turn **plus four continuation action turns**; this local bound is not the UTC spend limit. Git blame locates its introduction in fc6fe31: the loop returned action results to the model after a live shelter plan ended too early. Architecture and the bounded-chat test establish finite request work and yielding to newer chat as intended; the precise choice of four is undocumented.

## Approach for review

Adapt the single-owner agent pump and `Controller.next_turn`. When a direct command reaches its existing slice cap with `more` true, keep one **in-memory continuation ready for a model response**, never a directive to replay the preceding actions. Preserve the original player/request and episode; `Decision.messages` including provider reasoning blocks; effort; exact results by call ID, including failure, skipped calls and the precise `say` result; the failure bit, voiced state and original promise-check note when applicable. `next_turn` already appends result messages keyed by IDs before asking the model; reuse that protocol and do not dispatch the saved decision again. Preserve the specific failure note and speech state so single-voice handling remains truthful.

At the next normal loop cycle, process incoming addressed chat and safety-critical body events first. Only if the continuation still owns the flow and its world/character identity, deadline and budget remain valid, take it once and execute its next controller response. A ready continuation takes precedence over proactive reviews and new Director scheduling: prevent `_review_tick` or `Director.tick` from starting competing work while it is pending. Existing body situations must not overwrite it silently: process urgent safety first, and explicitly invalidate/report it if that processing establishes a new owner; otherwise retain and resume with fresh state. Recheck for addressed chat at the handoff itself. Cancel, pause, a newer addressed replacement, a new pending goal/Director-owned work, or world/character identity change invalidates it rather than reviving the old request. The normal model decides the new request; no phrase classification, automatic task creation or implicit goal is introduced. Empty/no-action responses, standing tools, and model-selected goal/skill retain existing semantics. Do not start model calls on idle ticks when no continuation exists.

Use the existing four-turn slice, and provisionally permit **one** additional four-turn continuation slice, for a finite total of initial plus eight continuation action turns. This smallest extension permits a sixth action and preserves a concrete resource ceiling; it is not a semantic success or progress judgment. Apply a provisional five-minute monotonic request deadline at safe boundaries and existing body/provider timeouts, never pretend it preempts a blocked call. On second-slice exhaustion, deadline, provider error, denied budget, or invalidated ownership, log the precise reason and deliver at most one honest incomplete/interrupted line using existing single-voice behavior when communication is possible; never claim success from the cap or model speech. No semantic no-progress comparator is proposed. Counts are resource ceilings and may be reviewed against latency/cost, not a substitute for predicate evidence.

**Provider admission is not yet per request.** Source audit found no `BudgetedLLM` in the deployed tree or candidate. `LiveAgent._run` checks `budget.allows("chat")` once, `_review_tick` and `Agent.step` check their own boundaries, but `Controller._complete` calls `self.llm.complete` directly. Therefore nested look loops, final-pass and talk-only calls are not separately checked by the production budget layer. Reuse `Budget` and enforce admission at the common `Controller._complete` boundary for every controller provider call (including continuation and nested read/talk paths), with a fail-closed autonomous check on absent reader, incomplete first read and known reader errors; stale-cache age hardening is deferred; preserve the existing external `Capped` hard request count when used. The existing `Budget.allows("chat")` has a read-error grace, so it alone cannot justify claiming fail-closed per-provider admission; the implementation must explicitly test the intended behavior rather than assume it. Account for optional warm-up separately. Budget polling is asynchronous, so reserve headroom and do not claim an instantaneous hard dollar limit. No new model-budget framework is specified.

**Director contract:** no continuation from a directed board run may escape its synchronous `run_directed` call. Source: `Agent.run_directed` returns `ended` values normal/chat/interrupted/error; `Director._advance` first evaluates the real success predicate regardless of that status, then for failed predicates treats only chat/interrupted as uncounted, while error currently falls through ordinary counted progress logic. Consequently neither inventing an `incomplete` enum nor labeling resource exhaustion as chat/interruption is justified. Leave Director behavior unchanged in this scope: retain its existing bounded run and accurate existing `chain_stopped` trace, and separately investigate its consumer contract before any new directed-exhaustion behavior. This proposal changes direct command continuation only and must not imply board-run completion.

**Restart scope:** continuations live only inside the active process and belong to its verified world/character. Never automatically replay one across a process restart. Existing episode logs and operational handoff record the last known action/results; a crash may leave the outcome unknown and no immediate user-facing line can be guaranteed. On orderly shutdown, if possible, report an interrupted pending continuation once. Crash recovery must not infer that a side effect failed or repeat it blindly. No new durable queue, lifecycle file, state migration or automatic cross-world restoration is proposed.

## Principles and acceptance

The model retains tool and argument choice; no item/task special cases or phrase maps. Actions use game input, results are evidence, and one owner/voice is preserved. No principle exception requested.

Offline tests with actual Agent/Rig/FakeLLM and mock body: (1) a generic request needing more than four continuation turns completes across slices, each action executes once, prior assistant thinking/tool call IDs, exact result, say status and promise note survive; (2) boundary addressed chat, cancellation, pause, world/character change, new pending goal and Director work invalidate before another old action; (3) body safety/reflex events take precedence without silent replacement and proactive/Director work does not overtake a valid continuation; (4) finite total slices, deadline, blocked/first-read/unreadable budget, provider error and shutdown are honest and bounded with no idle provider calls; nested read, final-pass and talk-only provider calls each perform budget admission; (5) standing tools, empty responses and queued goals remain valid, directed run consumer/predicate and existing interruption tests unchanged; (6) restart does not replay ambiguous actions, unknown remains unknown and no cross-world carry; (7) held-out non-survival compound request. Only after independent review, targeted/full tests, and developer-driven dev validation should a bounded unassisted diagnostic measure native outcomes, interruption behavior, elapsed time and spend. Do not weaken judges or count speech as outcome.

## Implementation notes

The session marks live continuations as budget-required; fake and dry sessions retain reader-free compatibility. Budget records whether a spend read completed successfully, independently of the timestamp written before a read begins. This does not establish cache freshness. Admission checks every nested controller request while a continuation is running and preserves ordinary chat grace. Current client get_state does not independently expose reflex ownership: pause/unavailable state prevents continuation, safety events are processed first, and the existing body arbiter remains authoritative over actions. A missing native character name or pawn denies live continuation; it is not interpreted as identity proof. No separate game-side probe or detector is introduced.

The implementation rechecks event routing, ownership epoch, fresh character state including explicit dead/paused, and budget after each deferred provider response and before each action; model responses invalidated by a newer addressed request are discarded without a competing voice line. Rechecks do not make the interval between the last state read and the body action atomic: the existing body arbiter remains authoritative. There is no fresh-cache age guarantee and no independent reflex-owner field. If an ambient chat arrives while a deferred provider response is in flight, retain the returned decision as pending dispatch and wait for normal chat routing. After ignored chat, dispatch that decision once without reissuing its provider call or prior action; a newer addressed or model-selected replacement invalidates it. Original deadline, turn counter and provider limits carry across the deferral. Read-only tool rounds may finish before dispatch is deferred; their results and calls are not replayed.

When ambient chat arrives between two model-selected actions, the pending dispatch also carries the next action index, completed per-ID results, accumulated outcome and held/speech state. After ordinary chat routing the remainder runs from that index, with the same deadline and turn count; no already-executed action is replayed. If ambient chat arrives immediately after the last action, its completed results instead wait for the next model turn. A newer addressed command supersedes either pending phase.
