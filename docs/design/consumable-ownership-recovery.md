# Consumable ownership recovery

- **Goal:** command, stay-fed and combat uses cannot overlap or credit another in-process use; uncertain outcomes remain truthful.
- **Evidence (UTC):** at 15:04:02Z command hydration rose 19.5â†’29.5; at 15:04:03Z another command and fed-reflex use overlapped, and that command failed verification at 15:04:09Z. Reflex use at :09 verified later. `skills.start_consume` invokes `inventory.use` before `run_job` acquires its pawn token; `inventory.R.tick` calls `M.use` independently. Overlap is established; cooldown or other game restrictions remain hypotheses.
- **Decision:** reuse `arbiter` for pawn priority and `skills.run_job` lifecycle, plus one shared in-flight **consumable transaction** in inventory's global hot-reload state. Pawn ownership alone cannot serialize cure and heal under one combat token. A transaction is a unique generation/id bound to the current arbiter token, caller, item and verification phase. Proposed inventory API: begin(token, caller, item) atomically checks current pawn ownership and no active transaction; press(id, token, ...) rechecks both immediately before actual use; finish/cancel(id, token, outcome) verifies identity and releases exactly once. Every use entry point must fail closed for missing/stale owner or transaction; recheck identity after any reentrant call. API names are design placeholders, not a second competing pawn arbiter.
- **Required caller scope:** move the command's initial input and baselines into its held job step; migrate fed drink/eat/heal and combat cure/heal, including both operations sharing one combat token. Audit and gate direct `inventory.use` access and `inventory.equip` when a selected hotbar slot is consumable (it triggers use); unconverted paths must fail closed, not bypass the transaction. Preserve non-consumable equip/use behavior. Inventory hot-reload instances must consult the same global transaction state.
- **Priority and inputs:** ordinary fed reflex yields without blocking to existing command, combat and modal owners. Safety-floor emergency may request bounded reflex-priority preemption using existing arbiter semantics, never bypass a higher/equal owner or loop indefinitely; record and surface interruption. Its modal leave must respect the actual modal owner and acquire appropriate ownership before injecting, as must optional reflex collection and every other reflex input. No forced modal closure or moving/stopping another owner's pawn. If safe acquisition/owner identification fails, defer and report the specific reason.
- **Lifecycle:** hold transaction through bounded verification; check real token and transaction id before press, after calls and while polling. Success/failure, timeout, bridge cancel, suspension/replacement, combat interruption, reflex stop/start, module reload, world pause and lease expiry must release or invalidate once. An interrupted transaction is unverified, never replayed or marked as a failed-item strike. Never resume a prior press automatically. Nil/invalid stat or count baseline is unknown, not zero. After a post-press interruption, return a specific unverified/interrupted outcome: the old waiter cannot later claim success, resume or replay. Retain the shared gate until that transaction’s original bounded verification window expires; if a prior transaction remains unresolved, defer the next or report ambiguity. This uses the existing verification window, not an invented extra quiescence delay. An uninterrupted transaction may report the observed matching stat/count delta as the current implementation does; independent same-item/stat changes and arbitrarily delayed prior effects remain causally indistinguishable without source-associated evidence. Do not claim absolute attribution or assert a game cooldown without game evidence.
- **Generality and principles:** one transaction per real use, independent of item, phrase and location; real game input and observed state only. This is deterministic ownership and outcome reporting, not a model-choice override. No gameplay result is synthesized.
- **Acceptance:** fake-engine regressions cover pre-grant/no-token and stale/reentrant token, command versus ordinary reflex, safety-floor preemption with modal ownership, combat heal versus cure on one pawn token, consumable equip/raw use, nonconsumable unaffected, input/verification interruption and cleanup across pause/reload/timeout/stop, nil baselines, an interrupted waiter and retained gate through its original window, deferred subsequent use while unresolved, concurrent same-item changes with the documented attribution limit, and no false strikes or replay. Ordinary uninterrupted matching deltas remain observable success, without claiming engine-source correlation. Offline tests first; later dev measurement uses live reservation and budget. No source implementation until fresh review approves this revised evidence boundary.

## Evidence boundary revision

The gate serializes known in-process inputs and their existing bounded verification windows. It cannot exclude independent changes or arbitrarily delayed effects after the window; observations remain truthful game-state evidence, not proof of their source. This revision retains useful uninterrupted verification while making interruption and unresolved overlap explicit.
