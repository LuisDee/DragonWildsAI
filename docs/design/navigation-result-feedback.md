# Navigation result feedback

## Goal and approach

A failed `go_to` should tell the model what the existing route computation and final position actually showed, so it can choose its next action. Do not change requested XYZ, strict arrival checks, movement, route admission, retry count or querying. The existing oracle response already carries a boolean-or-unknown `goal_projected`, boolean-or-unknown `partial`, and optional route points. Its last point is a **route endpoint**, not necessarily the projected goal; projected XYZ is not in the current response and stays unknown. No new producer or wire field is needed for this wave.

In `move.lua`, snapshot the exact resolved XYZ as **new metadata only** when each v2 route request is sent. On its matching epoch/nonce/request response, compare that snapshot with the current exact goal, plus the existing generation/token/pawn/world identity; only then retain bounded primitive evidence: requested resolved XYZ, boolean-or-unknown `goal_projected`, boolean-or-unknown `partial`, and the finite last route endpoint if present. This metadata check must not change existing route admission or its repath threshold. A valid matched `no_path` may preserve a false projection flag, with no endpoint; stale, malformed or transport-failed responses have unknown evidence and may never reuse an older endpoint. Preserve boolean false explicitly. The actor/name/coordinate originally supplied to `go_to` remains separate from the resolved XYZ and is not replaced by an endpoint.

Keep this evidence bound to its initial move generation and exact goal. A local water detour does not transform its origin or label its waypoint as an oracle endpoint. On terminal failure, before `finish` releases ownership, re-read and validate current pawn/world/goal and generation/token identity, then capture a fresh finite final position; horizontal error is XY distance, signed vertical error is final Z minus requested Z, and absolute vertical error is its magnitude. Unavailable or invalid facts remain unknown; do not infer walkability. Recheck identity around reentrant calls and do not let the old move mutate its successor.

The existing bridge go-to action polls global move status. Capture the initial accepted generation **for evidence only**, and propagate the bounded terminal metadata only when generation and provenance match. Arbiter suspension stops the original mover and restoration can create a new generation. In that case, or if lineage/identity is unproven, omit the new metadata entirely: do not rebind to the newest generation, invent a lineage system, add a new interrupted result, or change existing polling, cancellation or arrival behavior while restored movement continues. Keep exact original argument and its separate resolved XYZ when proven. `move.lua`, `client_bridge.lua`, focused Lua tests and this note are the only expected files; projected-goal XYZ or producer/protocol expansion needs separate design review.

## Acceptance and principles

Offline actual-module tests use the shapes of the 13 saved raw request/reply pairs without committing private logs: matched `no_path` with `goal_projected=false`; a partial path with a remote endpoint; a complete path whose endpoint and pawn height differ from requested height; and unknown/malformed flags or coordinates. Cover bounded output, final horizontal/vertical errors, same-generation bridge propagation, stale nonce/epoch/world/pawn/owner/exact-goal metadata rejection without altering route admission, late reply, movement replacement, suspend/resume with new-generation metadata omitted and no new terminal failure, water detour and stop cleanup. Include a valid matched no-path response with false flag, malformed or transport failure with no old endpoint, finite final-state identity recheck and signed plus absolute vertical error. Assert exact arrival behavior is unchanged and the provider receives a failure with original requested XYZ rather than a silently corrected target. Then perform one controlled developer check with independent route/result and strict idle evidence, followed by a bounded Haiku trial on the tested deployment. The server oracle may stream corridors and rebuild links: it is not a read-only diagnostic. This follows PRINCIPLES: real paths and verified facts, model-owned choices, generic behavior, one owner and preserved judges.
