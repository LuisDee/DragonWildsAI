## Goal and evidence
Every returned model response from the Director's skill-learning worker must reach the existing shared spend reader exactly once, including an invalid proposal that needs repair. Check the existing daily budget before each request. Preserve the [Accepted steer](autonomy-plan.md#accepted-steer--luis-2026-10-28), complete Sonnet Director + Haiku Controller, original M1-M6 and frozen judges. Private response lines/call numbers 8 and 9 are Sonnet skill distillation and its repair: their prompt/completion/cached/cache-write counts are respectively 5387/220/0/5383 and 5710/391/5383/323. The other 22 records match one-for-one, without extras. Those two signatures were absent from every spend-recognized file. This patch must not backfill or replay them again.

The source cause is `Director._maybe_learn`: its worker creates `SkillLibrary(lib_dir)` with `log=None`. `SkillLibrary.propose` already logs each response before validating it, but its `_log` silently does nothing without that logger. It also makes repair requests directly after only the Director's initial daily-budget check.

## Approach and ownership
Touch only `brain/director.py`, `brain/skill_library.py`, this note and one focused regression file, `tests/test_skill_learner_accounting.py`. Root owns integration, ledger mutations, navigation and live validation. Fresh Sol design review returned CLEAR; root then authorized this exact implementation scope.

1. Pass the Director's existing session logger to the worker's private `SkillLibrary`. Keep the private library/SQLite instance and main-thread `accept` boundary. The shared `JsonlLogger` already serializes appends under its lock and isolates episode context by thread; Director decisions already log through it from the worker.
2. In `propose`, render each admitted prompt through existing `request_log_fields`. Log `component=skill_learner`, explicit model and repair-round index, complete messages/tools/settings and the truthful request boundary. A custom wrapper remains labelled `llm.complete`; do not claim its final provider HTTP body is captured. Preserve the wrapper's independent inner-adapter evidence where used.
3. Immediately after `llm.complete` returns, emit exactly one existing-kind `llm_response` record with explicit model, usage, finish reason, content, tool-call metadata and round. Do this before parsing, semantic checks or deciding whether to repair. The existing spend mapping already classifies `skill_learner` as `generators`; no second usage event, new ledger or spend-reader change is needed. Provider errors without returned usage must not fabricate a paid-response record.
4. Add an optional `before_request` callback to `SkillLibrary.propose`, defaulting to no new policy for existing callers. Invoke it before the prompt record and provider request on every iteration, including repairs. Director supplies its existing daily admission check, equivalent to `not self._over_daily_cap()` / `budget.allows('director')`. False raises existing `BudgetStop` with a specific learner-budget reason; the worker collector preserves the failure through its current error path. No provider call or response-usage record is produced for denied admission. Do not recheck budget between a returned response and its usage log: an already paid response must be recorded even if admission has since closed.

Keep proposal parsing, faithful expansion, state postconditions, repair limit and final main-thread acceptance unchanged. Do not migrate the learner to a new decision framework or rewrite model choices. Keep the current initial hourly-learning scheduling/charge policy unchanged; it charges one submitted learning job and is not per-request hourly accounting. This wave repairs per-request **daily** admission and returned-response **spend** accounting only. The daily reader still uses cached aggregate spend and does not reserve worst-case dollars; root must retain conservative headroom and a bounded batch. Other optional-callback callers do not acquire a new budget policy implicitly.
