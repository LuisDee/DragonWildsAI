# Verify interaction-opened screens (2026-10-27)

## Goal and evidence

An ordinary interaction that opens a target's screen should report the observed result once, without closing it before verification or pressing use twice. In the developer-directed dev session, client log 22:15:21 records `IA_Interact`; at 22:15:25 orphan cleanup closed the Crafting screen and another press followed; at 22:15:27 cleanup closed it again, and at 22:15:29 the action failed verification. Separately, the native unlock query changed from false to true, unlocked-set count 83 to 90 and interacted-actor set gained the station class. A later real craft consumed eight logs and six stone with Artisan XP 16→36, and a later axe swing produced an Ash Stump and Woodcutting XP 206→219. These actions were developer-directed, not an autonomous benchmark success. The trace supports a false negative and a cleanup race; it does not prove every new screen was caused by the target or that the screen alone proves any recipe unlocked.

## Approach

Reuse the existing interaction episode, detector, input gate and screen APIs. Immediately before an accepted use press, capture a readable baseline of screen state and target-specific owner state. After the detector confirms the intended target and before sending the press, acquire a scoped screen claim for this interaction only; do not overwrite an existing owner. Existing claim/release functions overwrite or clear unconditionally, so check for conflicts and release only a claim still owned by this episode. Cover every terminal path, timeout, interruption, arbiter suspension, pause, cancellation and error. While held, the claim prevents orphan cleanup during verification. Existing `after_action` cleanup handles eligible screens; it explicitly excludes world-inventory and paused paths, so container cleanup retains its own lifecycle and pause requires deferred cleanup without native calls during pause. Never close another owner's UI. A survival/reflex preemption retains its existing authority; resume must re-baseline rather than credit a transition during suspension. Guard both initial and retry presses against open or unreadable UI. Do not change global orphan thresholds or disable cleanup.

Compare owners with the actor actually selected by the detector, including an accepted alternate target, rather than only the original requested actor. Verify the existing accessor for each family: `crafting.W.open_station` defaults to crafting and needs the processing kind for processing stations. A failed or nonboolean IsOpen read is unknown, not closed. These lifecycle clarifications were required by independent design review; implementation remains pending.

Verify a new screen only with a known closed-before/open-after transition **and target identity evidence** associated with this press. Reuse existing `crafting.W.open_station` (which reads the active station component's owner), `skills.W.open_container` owner, or another already supported native screen-owner signal when available; it must identify the same detector-selected target. Treat the existing station accessor as an implementation path to verify in this runtime, not proof that every UI exposes an owner. Missing/unreadable baseline, failed `IsOpen`, absent/mismatched owner, unrelated concurrent UI, or a pre-existing screen is not proof. `input.open_screens` currently collapses failed `IsOpen` calls to false, so this path needs a strictly readable result rather than treating an error as closed. Preserve existing gain/disappearance, same-container, sleeping, conversation and prompt-change checks and their stronger identity requirements. When a target-linked screen is observed, report its actual screen/owner transition; do not infer a later craft, unlock, dialogue, or inventory outcome. Never send a second interact press while a screen is open or its state is unknown; report a truthful failure if it cannot be attributed. Unknown native UI ownership remains a perception limit, not a reason to claim success.

The narrow candidate touches `client_mod/scripts/skills.lua`, `client_mod/scripts/input.lua` only if necessary for strict screen observation/claim lifecycle, and focused existing fake-world and input tests. Reuse `crafting.W.open_station` if its existing callable interface is usable without introducing a circular dependency; otherwise expose the same existing read-only observation through the smallest shared interface, subject to review. No target-name table, new generic framework, new native ABI, forced input, or emulated game result. Fresh-context review precedes edits.

## Principles and acceptance

This changes evidence and scoped ownership only, not interpretation of the player's words or selection of a target. The model remains responsible for composing actions; game state verifies each outcome; input uses real client paths. Preserve the one voice and do not emulate an interaction or suppress competing safety actions. No principle exception is requested.

Offline fake-engine regression must drive the actual interaction episode and real input cleanup together: a matching target's closed-before/open-after screen survives orphan ticks until verified, causes exactly one accepted press, is reported as observed and is cleaned after action; a pre-opened, unreadable, unrelated, mismatched-owner or transient screen never proves success and never causes a blind second press. Cover claim conflict, cancellation, suspension/reflex, resume, timeout, cleanup on failure, absent APIs, and preserve existing pickup, grave, bed, container and conversation cases. Test a second supported screen family and held-out interactables without category special cases. Run targeted Lua and design tests before the coordinated full gate. Live acceptance on the existing dev client must use a fresh relevant station or equivalent, capture detector target, screen/owner transition, input cleanup and exact press count, and independently observe progression only if that outcome is being claimed. Record version, resources and one live operator; the developer-directed outcome above remains separate from an autonomous measurement.
