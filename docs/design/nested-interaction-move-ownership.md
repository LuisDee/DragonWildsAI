## Proposed bounded ownership contract

Propagate the actual craft token to `_episode_poll` on every poll and use the already established arbiter token for the child. Fail closed before starting an episode-driven move if parent token is missing, suspended or no longer owns the pawn; do not silently adopt or start unowned movement. Validate ownership/life/pause and the same parent identity after any potentially reentrant checks, then issue the move. Record the exact movement generation returned by successful go_to together with token, pawn and episode identity. Do not set moving or accept child ownership if the returned generation is missing, invalid, or replaced before binding confirmation.

Before an episode exits approach for face, another spot, success, failure or cancellation, end only its still-active child: verify the raw current generation, token, pawn and owner match the recorded child, then use a minimal generation/token-checked stop operation compatible with the existing move stop binding. Never issue a global stop after a different generation/owner appears. Recheck after synchronous stop/cleanup callbacks: if replaced, leave successor unchanged and do not claim the old movement was stopped. If the owner is suspended or the world paused, do not issue native calls or release a foreign token; use arbiter's established suspend/stop lifecycle, invalidate stale child references and resume only from a fresh authorized episode. Before craft releases its own token on terminal paths, settle any still-owned child; failure/unconfirmed cleanup must not be presented as clean idle. Avoid broad arbiter changes, entity rules, memory deletion or preemption of the survival reflex.

`move.start` itself should reject an explicitly supplied invalid token and a nested missing-token request before it cancels an old handle, flushes memory, increments generation or starts a loop. Keep ordinary public direct moves working: they may adopt an idle-owner move under the existing implicit ownership path, but a missing token while an unrelated owner exists must not silently create an unowned move. This is an ownership admission distinction, not a hardcoded task or destination policy. `move.stop` may need a narrow expected-generation/owner checked path or existing context extension; preserve its existing arbiter stop-context protections and explicit-stop semantics. Do not introduce a generic unconditional idle reset.
