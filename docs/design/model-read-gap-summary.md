# Generic repeated read-gap summary: design for review

## Problem and boundary

The 2026-10-28 pilot log records a single raw `inventory` tool result of 13,068 UTF-8 JSON bytes: carried 166, loadout 8 and personal 20 gaps, each repeating the same reason with different raw slot indexes. The following controller prompt grew substantially; this observation does not establish why the model chose its response or that compaction changes that outcome. The raw body result is already logged by `Controller._read` before inventory enrichment, and `d.inventory` stores the enriched data for subsequent controller logic. `_loop` appends `tool_result_message(call, self._read(...))`, preserving the call ID in `brain/llm.py`. `next_turn` has another tool-result path for action results; this wave is scoped to inline read results, not arbitrary action history.

## Proposed behavior

At the Controller inline read result's **model serialization boundary**, after existing raw logging, enrichment, and assignment to `d.inventory`, create a copy for the tool-result message. Traverse only explicit `read_status` / `inventory_read_status` dictionaries and nested scope dictionaries. Within each scope's `gaps` list, group repeated *simple* `{raw, reason}` entries with the same string reason, retaining an exact per-reason count, up to three representative raw indexes, an explicit omitted count/truncation flag, and order of first appearance. Keep unique or short groups unchanged; keep unusual/richer rows (extra keys, malformed values, nonstandard details) verbatim so their actionable information is not discarded. Keep scope `status`, `reason`, `count_semantics`, held sides, every positive item, quantity, name, location, tool result `ok`/failure, and all other fields unchanged; absence remains unknown. Never infer an empty slot, change body response, modify `d.inventory`, or mutate shared raw objects. `tool_result_message` continues to receive the original ToolCall and its ID. Preserve complete original `tool_result` logger entry as today. When the existing CANT_YET failure presentation applies, retain its original failure fields as well as its explanatory note; do not replace error details with a generic summary.

This is generic by schema, not tied to inventory/item names or particular error phrases. It does not prescribe a tool or plan, change a model choice, edit logs, or assert gameplay success. Use the standard JSON structure and existing controller flow; no context-editing service or blanket text truncation. The same three-representative prototype on the actual raw logged result produced **1,884 bytes versus 13,068 bytes** before enrichment; target a meaningful fixture reduction, not a token guarantee. Actual enriched prompt sizes may differ. Reasons with distinct details remain separate; if all entries are unique/rich, preserving them may intentionally yield little reduction.

The original object remained unchanged. Raw local measurement:
`W/logs/recovery/model-gap-recorded-measurement-20261028.json`. This is a
serialization replay, not a provider token measurement or behavioral result.

Use real `Controller._read` and model loop with FakeLLM/mock game: inventory response → raw log → enrichment → tool result → next model input, proving matching tool_call_id, identical positive rows and non-gap fields, status/partial/lower-bound and distinct rare reasons, exact group counts/sample/omitted counts, no false empty result and original unmodified raw/enriched state. Exercise failed read with detail, malformed and missing gap shapes, nested held/per-scope statuses, multiple different groups and fewer than four entries, duplicate calls, and unrelated `gaps` fields. Compare UTF-8 prompt bytes on a fixture modeled on the logged 166/8/20 gaps and assert reduction without asserting an LLM behavior. Focused tests and design checks precede independent source review; current-code developer-driven then bounded model validation require the existing single DEV client slot and budget. The pilot's causal hypothesis remains unproved. No runtime/native/judge changes in this design wave.
