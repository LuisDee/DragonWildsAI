# Director decision contract (2026-10-27)

## Goal and evidence

The Director should be able to choose either immediate help, work, or completion without a conflicting field causing its chosen work to be parked before it starts. On deployed `cde20004`, `brain-live-20261027-225655-8912.jsonl` records a replan for task `552d7ceb` with five steps and a conditional `ask_help`. `Director._apply` calls `_ask_help` immediately when that field is present, before installing the steps; the task waited for help. The log establishes the incompatible response and its application, not why the model supplied it or whether any proposed game action would have succeeded.

## Approach

Keep the existing single JSON object and `Validator`/`json_decision` feedback loop; do not rewrite model decisions. Clarify in the Director output contract that `ask_help` means ask and wait **now**, so it cannot accompany proposed `steps`, `add_tasks`, `loops`, or `done`. A conditional future question should be reconsidered if the current work later fails. A work decision may contain steps and any applicable prerequisite task/loops; `done` is the mutually exclusive choice to end an open-ended job, not a companion to work or help. Preserve description, facts, capability-gap information and the existing first-plan success test as metadata; do not infer a choice from prose. Validate conflicts using the original supplied fields, before filtering/truncation can hide a mixed answer. Return a specific validation error explaining the incompatible fields and request a corrected object through the existing bounded repair loop; if repair fails, preserve the established explicit decision-failure behavior. Never silently delete, reorder or prefer one of the model's alternatives.

Review and reflect may legitimately return an empty no-change decision, retaining the current plan; preserve that behavior. Existing valid immediate-help decisions must still park and notify, and valid work decisions must still install and execute steps. Test whether `done` is restricted to open-ended jobs in the validator, matching `_apply`; an invalid use should be rejected rather than silently ignored. Keep current compatibility for predicates, metadata, researched facts, and normal prerequisite plans. No benchmark-specific text, phrase parsing, automatic station interaction or scripted work is introduced.

Fresh review approved with these constraints: validate raw field shapes before filtering, including boolean `done` and string `ask_help`; reject loops without steps because the apply path cannot install them in review/reflect; retain prerequisite-only review/reflect decisions. Empty/null/false values do not select a decision. Keep existing repair and per-request budget limits, including failure after exhausted repairs.
